# todo-scan

Находит в проекте комментарии `TODO`, `FIXME`, `HACK`, `XXX` и `BUG` и выводит их строками `файл:строка`
(такие строки кликабельны в большинстве редакторов и терминалов), в виде JSON или как проверку для CI.

- **Без зависимостей.** Только стандартная библиотека.
- **Учитывает `.gitignore`**: список файлов берётся у git (`git ls-files`), поэтому вложенные `.gitignore`
  и правила с отрицанием работают так же, как в самом git. Папки `.venv`, `node_modules`, `__pycache__` и
  похожие пропускаются всегда, даже если в проекте нет `.gitignore`. Без git утилита просто обходит папки
  и предупреждает, если это случилось внутри репозитория.
- **Эвристика, настроенная на обычный код.** Тег считается только сразу после символа комментария, поэтому
  фраза `# Handle TODO items` в отчёт не попадёт. Это не разбор кода, так что некоторые похожие места всё же
  срабатывают, см. [Известные ограничения](#известные-ограничения).
- **Для CI.** `--fail-on FIXME` завершает программу с ненулевым кодом, если найден выбранный тег.

[English version](README.md)

## Установка

```bash
pipx install todo-scan      # или: pip install todo-scan
```

Нужен Python 3.9 или новее.

## Использование

```console
$ todo-scan app
app/main.py:2: TODO(ann): handle missing files
app/main.py:6: FIXME: not atomic, can corrupt the file on crash
app/util.js:1: HACK: remove once the API returns ISO dates
Found 3 in 2 file(s) (FIXME: 1, HACK: 1, TODO: 1); scanned 2 file(s)
```

Находки идут в stdout, итоговая строка в stderr, так что перенаправление вывода остаётся чистым.

```bash
todo-scan                                   # текущая папка
todo-scan src tests/test_api.py             # несколько путей
todo-scan --tags TODO,NOTE                  # свои теги (ЗАГЛАВНЫМИ буквами)
todo-scan --exclude "*.min.js" --exclude vendor
todo-scan --format json > todos.json
todo-scan --fail-on FIXME,BUG -q            # для CI: ошибка, если есть FIXME или BUG
```

Остальные опции описаны в [английской версии](README.md#usage).

## Коды выхода

Смысл кодов `0`, `1` и `2` фиксируется с версии 0.1.0. Любой код, кроме `0` и `1`, означает, что результату
нельзя доверять. В будущем могут появиться новые коды, поэтому неизвестный код стоит трактовать как `2`.

| Код | Значение |
|---|---|
| `0` | Скан завершён чисто, тегов из `--fail-on` не найдено. Сами находки код не меняют. |
| `1` | Найден тег из `--fail-on`. Этот код важнее `2`: проверка провалена, что бы ещё ни случилось. |
| `2` | Результату нельзя доверять: неверные аргументы, путь не существует или его нельзя прочитать, **неполный скан** (папку или файл не удалось прочитать, git сбойнул или выдал предупреждение внутри репозитория), не удалось записать вывод либо произошла внутренняя ошибка. Подробности идут в stderr строками `todo-scan: warning: ...` (в том числе при `-q`) и в поле `warnings` JSON-вывода, где `summary.complete` равно `false`. |

Если читатель закрыл канал раньше времени (`todo-scan --fail-on all | head -n1`), код выхода от этого не меняется.

Фильтруются только папки *внутри* переданного пути, поэтому `todo-scan --no-git .venv/lib` просканирует ровно
то, что указано. Без `--no-git` список файлов определяет git: если `.gitignore` игнорирует переданную папку
(а `.venv` он обычно игнорирует), git ничего не вернёт, и вы получите 0 просмотренных файлов и код 0.
Чтобы просканировать игнорируемую папку, используйте `--no-git`.

## Известные ограничения

Они известны и запланированы на следующие версии, сообщать о них как об ошибках не нужно:

- Это построчная эвристика, а не разбор кода. В отчёт попадёт всё, что похоже на символ комментария с тегом
  после него: строковый литерал (`s = "# TODO: x"`), заголовок Markdown (`## TODO list`) и арифметика, потому
  что `*` и `%` тоже считаются символами комментария (`x = 2 * TODO`, `a % TODO`).
- Тег находится только в строке, где перед ним стоит символ комментария. В блочном комментарии находятся
  строки, которые начинаются с `*` (обычный стиль Javadoc). Строка продолжения без `*` в начале не находится.
  Строка docstring находится, только если у неё есть собственный символ комментария: текст сразу после
  открывающих `"""` на той же строке или строка, начинающаяся с `#`, `*` и так далее. Голое `TODO:` на
  следующей строке не находится. На одной строке находится только первый тег.
- Теги только ЗАГЛАВНЫМИ буквами: `todo:` игнорируется.
- Файлы читаются как UTF-8, недопустимые байты заменяются, а не обрывают скан. Файлы UTF-16 содержат
  нулевые байты и считаются бинарными.
- Папка, которую игнорирует `.gitignore`, даёт пустой результат, даже если передать её явно. Используйте
  `--no-git` (см. [Коды выхода](#коды-выхода)).
- Предупреждения git, кроме `could not open directory`, игнорируются. Если файл `.gitignore` нечитаем, git
  предупреждает и применяет меньше правил, так что в отчёте могут появиться находки из файлов, которые
  должны были игнорироваться. Скан при этом не считается неполным, потому что ни один файл не пропал.

Молча пропускаются намеренно: символические ссылки, FIFO и другие особые файлы, а также папки вроде `.venv`
и `node_modules`. В итоговой строке учитываются как пропущенные (это не ошибка): бинарные файлы и файлы
больше `--max-size`.

Выводятся как предупреждения, а код выхода равен 2, потому что скан неполный:

- папку или файл не удалось прочитать, в том числе отслеживаемый файл в папке, в которую нет доступа;
- предупреждение git `could not open directory`: git печатает его, но всё равно завершается с кодом 0,
  а файлы из этой папки в его списке отсутствуют;
- вызов git не удался внутри репозитория. Утилита всё равно сканирует, обходя папки, но `.gitignore`
  **не** применяется. В предупреждении цитируется ошибка самого git, например «dubious ownership».
